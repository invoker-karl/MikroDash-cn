# Interface translations

MikroDash keeps English as the source language and applies optional browser-side
translations from `public/locales/`. This keeps upstream merges small while the
large static and Socket.IO-rendered interfaces share one translation layer.

## Runtime and locale policy

- `public/i18n.js` handles detection, persistence, DOM translation, dynamic
  nodes and translated attributes.
- `public/locales/en-US.js` is the source-language fallback.
- `public/locales/zh-CN.js` contains Simplified Chinese exact strings and
  narrowly bounded dynamic patterns.

The choice is stored as `mikrodash-language`. `zh`, `zh-CN`, `zh-SG`, and
`zh-Hans` select Simplified Chinese. Traditional locales (`zh-TW`, `zh-HK`,
`zh-MO`, and `zh-Hant`) deliberately fall back to English rather than showing
the wrong writing system.

## Updating translations

Add an exact source string to `messages` whenever possible. Put
`data-i18n-user-data` on the smallest element containing a router/device/user
name, SSID, log line, or other server/user value. Use `data-i18n-skip` for a
whole component that must never be translated.

Patterns are only for well-defined numeric/status forms. Never add a catch-all
such as `No (.+) found`, `Save (.+)`, or `(.+) ago`: captured content can be
user data. Every pattern needs positive and negative tests.

Run `npm run i18n:audit` after every upstream sync. It extracts visible text,
placeholders, titles, and ARIA labels from both entry pages. Every English
candidate must be translated or classified with a narrow reason in
`i18n/allowlist.json`; the gate does not accept a dictionary-size threshold.
Runtime-only misses can be inspected without changing the display:

```js
MikroDashI18n.enableAudit(true);
MikroDashI18n.getMisses();
```

Tests cover dynamic nodes and attributes, language round-trips, user-data
boundaries, pattern counterexamples, and observer recursion safety.

## Upstream safety policy

`main` is the reviewed stable Chinese branch. It must never be hard-reset to
upstream. `.github/workflows/upstream-review.yml` merges upstream into the one
`automation/upstream-review` branch using a normal non-forced push and opens a
review PR; it never auto-merges.

The wei/pull GitHub App's no-config Basic Setup hard-reset mode previously
erased Chinese history. The app must be uninstalled or restricted before this
branch becomes default. `.github/pull.yml` disables its merge method as a
second line of defence, not a substitute for removing write access. Protect
`main` and require the test workflow before merging an upstream review.

## Release policy

Only an exact `vX.Y.Z-cn.N` tag can run the release workflow. It publishes an
immutable version image for `linux/amd64` and `linux/arm64`, verifies both
platforms, and then makes `latest` point to that same manifest digest. Pull
requests have read-only permissions and never publish packages.
