# Interface translations

MikroDash keeps English as the source language and applies optional browser-side
translations from `public/locales/`. This avoids rewriting the large static HTML
and JavaScript views and keeps merges from the upstream project small.

## Files

- `public/i18n.js` — language detection, persistence, DOM translation and live
  translation of Socket.IO-rendered content.
- `public/locales/en-US.js` — source-language metadata and fallback.
- `public/locales/zh-CN.js` — Simplified Chinese strings and dynamic patterns.

The selected language is stored in the browser under
`mikrodash-language`. New visitors whose browser language starts with `zh` use
Simplified Chinese automatically; all other visitors use English.

## Updating translations

Add an exact English source string to the locale's `messages` object. Use a
pattern only for text containing live values, such as counts or timestamps.
RouterOS identifiers, interface names, addresses, protocol names and user data
should remain untranslated.

When syncing upstream changes, keep `main` aligned with the upstream default
branch and merge it into the translation branch. Most upstream UI changes only
require adding newly introduced English strings to `zh-CN.js`.
